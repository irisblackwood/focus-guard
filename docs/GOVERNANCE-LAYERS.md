## 一、一句话

**目标不是新造五层，是把已经跑了的三层半收口成一个判据：钥匙在宿主和用户手里，模型只能提议。**

五层里已有实现在跑，从零重写会让后来人再造一遍 `approvals.mjs`——那是真正的浪费。

## 四、排期

> 改正处：量尺原先排在手术之后，等于**没有术前基线**，改完无法判断好坏。现前移为第 0 步。

| 步 | 动作 | 编排版本 | 为什么在这个版本 | 判据 |
|---|---|---|---|---|
| **0** | 量尺：`bench-cost.mjs` 加读侧派生视图 | **3.3.2** | 3.3 系列本就是"尺子"；无基线则后续无法验收 | 三个比率可复算 |
| **1** | 堵钥匙：`focusguard.mjs approve` 进红线 | **3.3.2** | 现存越权路径，一条正则 + 一条夹具 | 模型调用即 deny |
| **2** | PATTERNS 骨架：熔断即写事实，教训留给模型 | **3.3.2（已完成 2026-11-03）** | 与第 0 步同哲学：引擎只写事实，不替模型下结论 | 熔断后文件必有骨架 |
| **3** | 收窄令牌：grants 追加 `scope` / `evidenceHash` | **4.0-P2** | P2 要重写审批表（会话注册表 / 审批表 / TTL），3.x 先改等于改两遍 | 带 ctx 才校验 |
| **4** | 立判据：指纹 vs 语义写进 ARCHITECTURE | **3.5.0** | 3.5 只交付文档，不夹带代码 | 一条判据 |
| **5** | 记忆标签分离 | **4.5 · M3** | 属记忆里程碑，不占 3.x | 见 MEMORY-4.5-PLAN |

**两处改动的理由**：

- **收窄令牌从 3.x 挪到 4.0-P2**：`MCP-4.0-PLAN` 的 P2 明确要重写审批表与 TTL。在 3.x 改 `grants.mjs` 的键，
  4.0 再重写一遍——这正是"补丁有累积迹象"的成因，也是本仓反复吃亏的形态。
- **量尺必须最前**：原设想排在手术之后，等于没有术前基线，改完无法判断好坏。

### 第 0 步：为什么量尺不加计数器

原设想是"给白名单命中加统计"，那要新增写入路径。改为**从审计流读侧推导**：

| 指标 | 公式 | 抓什么 |
|---|---|---|
| 命中率 | `(approval-consumed + ptc-auto-grant) / allow` | 白名单用得多不多 |
| 请求密度 | `approval-requested / 会话步数` | 模型反复请求同类豁免 |
| 集中度 | 走令牌的 allow 中不可逆类占比 | 白名单挤在高风险路径 |

三个量全部来自 `AUDIT.log` 已有事件（实测已落：`approval-requested`、`approval-consumed`、
`ptc-auto-grant`、`appeal-granted`、`grants-swept`），`approvals.mjs` / `grants.mjs` / `audit.mjs` 一行不动。

**为什么这样更美**：

- **零新增写入路径**：不加计数器，就不会出现"计数器静默不涨"（D4 最阴的一类损害）
- **分母可复算**：审计 append-only，历史任意重跑，比率不会被分母操纵
- **同范式**：与 `falsePositiveRatio` 同文件、同数据源、同算法，不引入第二套度量语言

### 第 3 步：为什么不改授权键

改键要动 `has / get / grant / revoke` 四处，是破坏性变更。改为**追加两字段**：

- **做法**：entry 上加 `scope` / `evidenceHash`，`has(tool)` → `has(tool, ctx)`
- **兼容**：无 ctx 时保持旧行为，旧调用全部照常绿
- **代价**：只在 `alive()` 里多一次比对，104 行的表不重写

## 五、第四层的实证：PATTERNS.md 空转（2026-11-03）

> 现象：PATTERNS.md 用了很久仍是空的。实测成立，且原因不在"没想起来写"。

| 事实 | 值 |
|---|---|
| 文件 | `.ai/PATTERNS.md`，182 字节，mtime **2026-10-07 13:15** |
| 内容 | 仅标题 + 一行格式说明，**0 条** |
| 写入方 | 仅两处 `writeFileSync`（`hooks/guard.mjs:1062`、`src/dsh/stopGuard.mjs:185`），**都是"不存在才建"，无一处追加** |
| 承诺方 | `constants.mjs:89` 提示词「解除后经验按 `[环境:x][任务:y]` 记入 `.ai/PATTERNS.md`」 |

**三处引用、零追加**——这是「写了但没连上」的第八例（前七例见 `VERSION-PLAN.md` §1.5）。

更麻烦的是模板自己写着「（79条）」，于是**空库自称有 79 条经验**。已在 2026-11-03 删掉该数字（数字无人维护，写死即为谎）。

**为什么测试没抓到**：`lifecycle.test.mjs:187` 只断言"文件已创建"，`acceptance.test.mjs:919` 只断言提示词提到文件名。**锁的是创建，不是写入**——所以永远绿。

**修法（已落地 2026-11-03）**：不自动追加"教训"（那要替模型判断该记什么），
改为**引擎写事实骨架、模型补判断**：

- **落点**：新模块 `src/core/patterns.mjs`（`appendPatternStub` / `ensurePatterns`）
- **时机**：熔断声明且**首次跃迁**（`!wasFused`）——重复声明不重复记账，另有"同会话同日"去重兜底
- **骨架内容**：时间 / 环境 / 任务类型 / 触发原因 / 证据（会话 id） / `教训：<待补>`
- **纪律**：引擎只写它确知的事实；`教训` 一行空着，模型补不了也不伪造

**为什么这样更美**：空库不再可能（熔断必然留下骨架），而"该记什么教训"这个判断题
仍然留在模型手里——与第三层"模型只能提议"同一条原则。

**测试**：`lifecycle.test.mjs` 增一条断言（骨架必须含 `教训：<待补`），此前只断言"文件已创建"。

## 六、审计保留：极旧数据为什么不清理（2026-11-03）

> 现象：AUDIT.log 里有极旧数据长期不清理。实测成立，原因是**判据只有一个维度**。

| 事实 | 值 |
|---|---|
| 活动日志 | 2,896,793 字节 / **10,256 条** / 首条 **2026-10-06** / 末条 2026-11-02 |
| 轮转判据 | 只有体积：`AUDIT_MAX_BYTES` 默认 **5 MB** |
| 实际后果 | 27 天只写 2.76 MB，**离阈值还差一半**，按当时速率约 45–50 天才轮转一次 |
| 归档目录 | 仅 3 个 10-18 手工清理留下的 `purge-bak`，**从未真正轮转过** |

**根因**：体积约束的是**磁盘**，年龄约束的是**可读性**——两件事，只做了一件。

**修法（已落地 2026-11-03）**：`rotateAuditIfNeeded` 改为**双阈值，先到先轮**：

- **新增**：`AUDIT_MAX_AGE_MS`（默认 30 天，`FG_AUDIT_MAX_AGE_MS` 可覆盖）
- **判定**：读首条记录 `ts`（只读头部 512 字节，不整读日志），超龄即归档
- **兼容**：第三个参数传 `Infinity` 可关掉年龄判据；体积判据原样保留
- **顺带修掉**：原注释写"只归档、不删除"，代码却在超出 `AUDIT_ARCHIVE_KEEP`（10 份）时 `rmSync`
  旧档——注释与实现相反，已改成"只归档活动日志、不删记录；归档保留最近 10 份"

**测试**：新增 `tests/audit-retention.test.mjs`，一条红路径——首条 31 天前、体积仅数十字节，
必须归档（此前这种文件永远不轮转）。
