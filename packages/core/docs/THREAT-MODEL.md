# 威胁模型（THREAT-MODEL）

> **状态**：权威 · 建立 2026-11-01 · 依据：2026-11-01 红队渗透（`44c44a2` / `0528653`）

## 一、一句话

> **本插件不防攻击者。它要防的是「插件自己把用户的机器/数据弄坏」。**

这条判据是 2026-11-01 人类定的原话（「dsh 很少会有插件被成为攻击吧，要修的是插件对使用的用户的电脑的损坏吧」）。
它把整张漏洞表重排了一遍：一半的"高危"当场掉出榜单，另一半才真正要紧。

## 二、攻击者模型：**无**

FG 是**本地单用户插件**，跑在用户自己的权限下。任何"攻击者"只要能碰它的文件，本来就能改用户机器上的任何东西——**没有可被突破的信任边界**。

由此推出三条**明确不做**（不是"以后做"，是"按判据不该做"）：

| 不做 | 为什么 |
|---|---|
| **目录属主校验**（`getuid` + 属主比对） | 只在**多用户主机**（共享 `/tmp`）成立。单用户桌面上不存在第二个能预建目录的人。已做的是成本为零的那半：显式 `chmod 0o700`（`mkdirSync` 的 mode 只对新建生效，这是真缺口） |
| **状态文件签名/防伪造** | 能写那个目录的人本来就能改任何文件。做了只增加复杂度，不增加安全 |
| **`FG_PYTHON` 白名单** | 那是**用户的配置权**。用户想用哪个 python 是用户的事。已做的是让它配错时可见（指不到就回退并留一行 stderr） |

## 三、风险模型：四类损害

按"用户会失去什么"分类，不按"技术上是什么漏洞"分类。

| # | 损害 | 判据 |
|---|---|---|
| **D1 删掉用户的东西** | 插件删了不是它建的文件、或删了用户写的字 | **删的每个文件都要能证明"是我建的"；证明不了就只删一次，不能永远删** |
| **D2 把用户的凭据漏出去** | 明文密钥被复制进工作区，然后被 `git add .` 推上远端 | 这是**唯一会溢出到用户之外**的一类，优先级最高 |
| **D3 写坏用户的文件** | 覆盖式重写吃掉表格以外的内容、跟随符号链接写到别处 | 引擎只拥有它自己写的那些行/字节 |
| **D4 功能静默失效** | 插件以为自己在工作，其实没有（熔断没装上、审计没写进去） | **「不阻断」和「看不见」是两件事** |

## 六、这份文档不覆盖什么

- **不覆盖 DSH / Electron 自身的启动性能**。实测 FG 在启动路径上的总贡献约 **75 ms**（模块图 37 + `detectEnv` 34 + `cleanStaleTemp` 2），不是启动慢的原因。
- **不覆盖提示词注入 / 模型越权**。那属于宿主与模型层，FG 只能拦工具调用，拦不住"模型说了什么"。
- **不覆盖供应链**（npm 依赖投毒）。本仓零运行时依赖，但构建链未审。
