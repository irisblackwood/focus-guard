# 记忆系统独立与 4.5 规划（MEMORY-4.5-PLAN）

> **状态**：参考 · 适用版本 3.3.0（4.5 前置）· 最后核对 2026-11-01
>
> 规划文档：与实现**尚未同步**，随 M1–M4 落地逐段转权威。裁决仍以 `ARCHITECTURE.md` 与 `VERSION-PLAN.md` 为准。

> 人类要求（2026-10-30 原话）：「记忆系统从今日是其独立模块，包括静态知识库也要进行改革；
> 对伪 RLHF 进行强有力的联动，加强完善其人格；要求在 4.5 版本之前完成。」
>
> 为什么是 4.5 不是 4.0：`VERSION-PLAN.md:26-27` 写死「4.0 只交付 Hook 完全态，不夹带」。
> 记忆系统不能塞进 4.0，否则重演"一版多主题、验收无法收敛"。故另立 **4.5** 里程碑。

## 一、现状测绘（2026-10-30 实测，不是推断）

记忆目前**散在三处、代码分属两层**，没有统一入口：

| 载体 | 内容 | 代码位置 | 问题 |
|---|---|---|---|
| `workspace.json` | 跨会话卷宗：决策 / 约束 / 下一步 / 快照 | `src/dsh/workspace.mjs` | 记忆逻辑住在**适配层**，脱离 DSH 就无法复用 |
| `.ai/CASE_FILE.md` | 四册卷宗（【一】目标 /【三】取证 /【四】额度 /【五】成本） | `src/core/state.mjs::casePath`、`src/dsh/audit.mjs` | 写入点散落，路径开关 `FG_CASE_FILE` 是后来补的 |
| `.ai/library` + `.ai/archive/library` | 静态知识库（108 份调研 + 12 份笔记） | 无 | **只有一份 README，没有索引**；`docs/INDEX.md` 只管 `docs/`，管不到它 |

人工维护工具已就位：`tools/lib/case-tool.mjs`（`fg case` / `--score` / `--tag` / `--drop`）。

**伪 RLHF 现状**：`docs/PROFILE-TUNING.md` 是人工批准制台账，但 **§四「批准留痕」自建立起一直是空表**——
一次闭环都没跑过。这不是"没有 A/B"，是"测量结论不回写、回写了也没留痕"。

## 二、目标架构

```
packages/core/src/memory/        ← 新模块，唯一入口 index.mjs
  index.mjs      统一出口（其他层只准 import 这里）
  workspace.mjs  跨会话卷宗（从 src/dsh/ 迁入）
  case-file.mjs  四册卷宗读写（从 state.mjs / dsh/audit.mjs 抽出）
  tags.mjs       标签解析（从 workspace.mjs 抽出）

packages/core/src/persona/       ← 另一个模块，不属 memory（2026-10-31 裁决，见 §二·补）
  index.mjs      人格档读写 + 注入投影

packages/core/tools/             ← 离线工具，不进运行时链路
  critic（待定）  伪 RLHF 打分器（4.5 之后，见 §二·补）
```

**§二 的两处修正（2026-10-31）**：
1. 原规划的 `knowledge.mjs`（静态知识库索引）**移出本模块**，落 `tools/`（已实现为 CLI 工具，无运行时调用方）。理由见 §二·补。
2. 原规划只字未提**人格档**——它是四档里唯一"不许衰减"的东西，与记忆层的设计前提相反，故另立 `src/persona/`。

**分层纪律**：`src/dsh/` 只做「宿主缝」，不再持有记忆逻辑；`src/memory/` 不 import 任何 `dsh/`。
判据：`grep -rn "from '.*dsh/" src/memory/` 必须为空——这条进 lint。
（注意：这条只查**方向**、不查**时机**——它管不住"把离线工具塞进实时链路"这类污染，故 critic 直接不进 `src/`。）

## 二·补 情感训练四档的归属裁决（2026-10-31，人类提问触发）

**起因**：人类问「伪人类情感训练四档都想要，该新开模块还是就在记忆层」。

**裁决口径**：模块边界按**变动节奏 + 失效半径**切，**不按功能主题切**。

| 档 | 要什么 | 载体 | 归属 | 判据 |
|---|---|---|---|---|
| 1 表达 | 说话像有情绪 | 提示词 | **不建模块** | 是档 2/3 的副产品；单独做就是表演 |
| 2 行为随历史改变 | 状态 + 回传 | 卷宗扩展（情绪位） | `src/memory/` | 一次行为改变能在下次会话被读到 |
| 3 人格一致 | 跨会话同一脾气 | 人格档 | `src/persona/`（新） | 三个月不写也不许衰减 |
| 4 自生成训练信号 | critic | 离线批量 | `tools/` 下独立工具 | 打分者与生成者**不同源** |

**三条硬理由**（不是偏好，是装不进一个模块）：

1. **写频率差三个数量级**。记忆层每天动——每次 `fg case --drop` 都走 `backupCase` 备份；人格档月级才改一次。混装的结果是人格档被反复备份、扫描、审计，全是噪音。
2. **失效模式相反**。记忆层的前提是「**可以错、可以丢**」：有 `--drop`、`[note]` 不注入、半衰期衰减。人格层的唯一硬要求恰恰是「**不可 drop**」。一条要求"衰减是功能"，另一条要求"衰减是事故"——同一套淘汰机制装不下两个相反的假设。
3. **档 4 是工具，不是运行时**。critic 要离线重放审计日志、批量打分，进注入链就是污染。§二 那条 lint 判据只查 import 方向、不查调用时机，**管不住**这类污染，所以它干脆不进 `src/`。

**只准开一个新模块时，开档 3，不开档 4**。critic 在档 2/3 攒够真实信号之前跑起来，只会对着空日志打满分——与本仓 `schema:verify` 空转 8 天、`PROFILE-TUNING.md §四` 空表是同一个病：**判据先于数据存在，就是制度在假装运行**。

**落地顺序：档 2 → 档 3 → 档 4，不并行**。档 2 最便宜（半衰期与卷宗都在手上）；档 3 便宜但卡在定义（见 §六 待裁决 D）；档 4 最贵且依赖前两档的数据积累。

**排期见 [`VERSION-PLAN.md`](VERSION-PLAN.md) §4.5.2**（排期是版本面的事，只在这一处记，避免两个真相源）。

## 四、伪 RLHF 联动（具体做什么，不喊口号）

「强有力联动」落成三条可验证的机制，不是加个链接：

1. **记忆操作进审计**：`memory-add` / `memory-tag` / `memory-drop` 三类审计行，带序号与原因。
   判据：`fg case --drop 3` 之后，`AUDIT.log` 里能查到「删了什么、什么时候、删前是什么」。
2. **记忆效果可测**：`[goal]` 条目在后续会话里是否真被引用（`prompt-prefix-shift` 已有观测能力，
   再加一条 `memory-hit` 记录"这条目标出现在第 N 次装配里"）。没有这个，"人格完善"无法证伪。
3. **台账不再空转**：每次 `memory-*` 操作若伴随参数/画像调整，必须在 `PROFILE-TUNING.md §四` 留一行。
   判据：§四 至少一行真实记录——空表就是"制度没在跑"的最硬证据。

**不做**：自动调参、自动淘汰、按遗忘曲线算权重。理由见 `ARCHITECTURE.md`「卷宗条目维护」一节：
时间衰减会先杀掉长期目标，而长期目标恰恰是最该留的那条。

## 五、静态知识库改革

现状：`.ai/archive/library/2026-10-08/` 108 份、`.ai/notes/` 12 份，**没有索引**，只能靠 `grep` 全量扫。

改革三条（对齐 `docs/archive/MASTER-PLAN-3.0.0.md` 第 31 行的 R1 主题6「索引与内容分离、查重删错」）：

1. **索引与内容分离**：内容不动，新增 `.ai/library/INDEX.md`（主题 → 文件 → 一句话摘要 → 日期）。
2. **查重**：同一主题多份笔记合并，重复段落标注来源而非删除（调研资料的价值在原文）。
3. **失效标注**：过时的外部事实（模型版本、价格）标 `stale@日期`，不删——删了就没人知道曾经这么想过。

## 五·补 外部参照：`memory-brain` 的可抄面（2026-11-01）

**出处**：`github.com/peterpoal134/memory-brain`，AGPL-3.0-or-later，2026-10-28 建仓，
2026-11-01 仍在提交（`f06386d4` 房间系统 API + DSH 包脱敏、`212309a1` 合入房间面板）。
自述「不是新算法，是一套可落地的工程整合」。它已分出 `dsh/` 通道（`dafeiyu-3d-brain` 3D 大脑 +
`persistent-self` 跨会话开机包），与 AstrBot 那套互不相干。

**许可证结论（先排除这一项）**：`-or-later` 允许按 AGPL-3.0 使用，可并入本仓的
`AGPL-3.0-only`（`package.json:57`、`NOTICE` 双许可）。**代码层面无阻**——这不是否决理由。

### 抄①：注入块 marker 化 + 重复注入先删旧块

它的硬约束原文：「人格文件只读，所有增强都是往 system_prompt 追加"注入块"；每个注入块带
marker，**重复注入先删旧块**；每个模块一个开关，默认关。」

这句话对准的是本仓**未修的 DRIFT**（`VERSION-PLAN.md` §1.5①）：
2026-10-27 实测 3 个真实会话中 **2 个 DRIFT**，`4cbe896a` 同一会话中途 system 出现两个版本
（`上次会话：session-c00d · 工具调用 116` → `上次会话：5a292b3a · 工具调用 4`）。
形态上就是**追加而不替换**：本仓把注入当一次性书写，它把注入当**可撤销的事务**。

**如实申报**：DRIFT 是否确由"追加"造成，**未验**。但「先删旧块」的形状本身是对的，
且直接给出 §1.5① 第三点待定项（漂移时只写审计 / 同时告警）的**第三选项**：漂移时替换旧块。

### 抄②：冲突检测

本仓有 `retention`（遗忘曲线）、`halfLifeOf`（什么值得记），**没有"两条规则打架"的处理**——
同一约束被两个来源说了相反的话时，现在只能靠后写覆盖前写，且覆盖本身不留痕。

它的做法：相似合并 + 冲突检测 + 体检（README「遗忘」一节）。可抄的是**冲突这个类别的存在**，
不是它的实现（SQLite + embedding）。归属见 §六 待裁决 E。

### 不抄：三件，理由不是"不好"

| 零件 | 为什么不能抄 |
|---|---|
| 五路混合检索（向量 + 关键词 + 实体图谱 + 重要性 + 新鲜度） | 本仓记忆的消费者是**闸门**，不是对话模型。闸门要的是"这个 AI 上次在边缘跳了几次"——`AUDIT.log` 8,540 行的结构化事件（路径=实体、action=类别、时间戳=新鲜度），`JSON.parse` 即可，投影 O(文件数) 而非 O(事件数)。它自报检索 p50 **120–140ms**（含 embedding）、纯检索 40ms——拿这个去查一个能直接算的东西，是拿显微镜钉钉子 |
| 生活层（不找你时看书 / 刷视频 / 午睡，笔记回流记忆） | **熔断器不午睡**。FG 没被调用时不应有任何动作 |
| PAD 三维情绪 | 它自己写「有上限、有半衰期、**不主导判断**」。那 FG 拿它做什么？FG 需要的不是情绪，是**偏置**——同一个错误被"第一次犯"无限次重演，缺的是前科，不是心情 |

### 不接运行时：两条硬理由

1. **破零依赖**：Python 3.12 + SQLite（`dsh/persistent-self` 还带 numpy，可选 Ollama / whisper）。
2. **它是 push，本仓必须 pull**：`persistent-self` 的用法是 `SelfView(conn).render()` **返回字符串**
   → 必然进 system prompt。这直接撞第一不变量（单一注入层）：两个都往 system 追加，
   谁先谁后、谁删谁的 marker、漂移算谁的。
   真要接，唯一安全形态：**FG 主动去问一句，结果进 deny 理由（尾部），不进 system**。

### 判据（写死，避免反复讨论）

> **记忆的消费者是闸门，不是模型。前科不需要被回忆，只需要在越线那一刻被想起来。**

本参照使 §六 待裁决 C（`memory-hit` 是否进注入）明显倾向 **① 只写审计不进注入**，
但裁决权仍在人类，不代拍。

## 七、边界（写死，避免误读）

- 本计划**不改** `workspace.json` 的 schema——标签仍用文本前缀，零迁移。
- 本计划**不做**自动淘汰、不做遗忘曲线、不做无人批准的参数回写。
- 本计划**不引入**任何外部记忆服务的运行时（§五·补）：零依赖是硬约束，抄设计不抄依赖。
- 4.5 之前若 M1/M2 未完成，**不允许**为赶版本跳过验收——宁可延后 4.5。
