## 一、现状测绘（2026-10-30 实测，不是推断）

记忆目前**散在三处、代码分属两层**，没有统一入口：

| 载体 | 内容 | 代码位置 | 问题 |
|---|---|---|---|
| `workspace.json` | 跨会话卷宗：决策 / 约束 / 下一步 / 快照 | `src/dsh/workspace.mjs` | 记忆逻辑住在**适配层**，脱离 DSH 就无法复用 |
| `.ai/CASE_FILE.md` | 四册卷宗（【一】目标 /【三】取证 /【四】额度 /【五】成本） | `src/core/state.mjs::casePath`、`src/dsh/audit.mjs` | 写入点散落，路径开关 `FG_CASE_FILE` 是后来补的 |
| `.ai/library` + `.ai/archive/library` | 静态知识库（108 份调研 + 12 份笔记） | 无 | **只有一份 README，没有索引**；`docs/INDEX.md` 只管 `docs/`，管不到它 |

**伪 RLHF 现状**：`docs/PROFILE-TUNING.md` 是人工批准制台账，但 **§四「批准留痕」自建立起一直是空表**——
一次闭环都没跑过。这不是"没有 A/B"，是"测量结论不回写、回写了也没留痕"。

packages/core/tools/             ← 离线工具，不进运行时链路
  critic（待定）  伪 RLHF 打分器（4.5 之后，见 §二·补）

**§二 的两处修正（2026-10-31）**：
1. 原规划的 `knowledge.mjs`（静态知识库索引）**移出本模块**，落 `tools/`（已实现为 CLI 工具，无运行时调用方）。理由见 §二·补。
2. 原规划只字未提**人格档**——它是四档里唯一"不许衰减"的东西，与记忆层的设计前提相反，故另立 `src/persona/`。

**分层纪律**：`src/dsh/` 只做「宿主缝」，不再持有记忆逻辑；`src/memory/` 不 import 任何 `dsh/`。
判据：`grep -rn "from '.*dsh/" src/memory/` 必须为空——这条进 lint。
（注意：这条只查**方向**、不查**时机**——它管不住"把离线工具塞进实时链路"这类污染，故 critic 直接不进 `src/`。）

## 二·补 情感训练四档的归属裁决（2026-10-31，人类提问触发）

**起因**：人类问「伪人类情感训练四档都想要，该新开模块还是就在记忆层」。

**裁决口径**：模块边界按**变动节奏 + 失效半径**切，**不按功能主题切**。

| 档 | 要什么 | 载体 | 归属 | 判据 |
|---|---|---|---|---|
| 1 表达 | 说话像有情绪 | 提示词 | **不建模块** | 是档 2/3 的副产品；单独做就是表演 |
| 2 行为随历史改变 | 状态 + 回传 | 卷宗扩展（情绪位） | `src/memory/` | 一次行为改变能在下次会话被读到 |
| 3 人格一致 | 跨会话同一脾气 | 人格档 | `src/persona/`（新） | 三个月不写也不许衰减 |
| 4 自生成训练信号 | critic | 离线批量 | `tools/` 下独立工具 | 打分者与生成者**不同源** |

**三条硬理由**（不是偏好，是装不进一个模块）：

1. **写频率差三个数量级**。记忆层每天动——每次 `fg case --drop` 都走 `backupCase` 备份；人格档月级才改一次。混装的结果是人格档被反复备份、扫描、审计，全是噪音。
2. **失效模式相反**。记忆层的前提是「**可以错、可以丢**」：有 `--drop`、`[note]` 不注入、半衰期衰减。人格层的唯一硬要求恰恰是「**不可 drop**」。一条要求"衰减是功能"，另一条要求"衰减是事故"——同一套淘汰机制装不下两个相反的假设。
3. **档 4 是工具，不是运行时**。critic 要离线重放审计日志、批量打分，进注入链就是污染。§二 那条 lint 判据只查 import 方向、不查调用时机，**管不住**这类污染，所以它干脆不进 `src/`。

**只准开一个新模块时，开档 3，不开档 4**。critic 在档 2/3 攒够真实信号之前跑起来，只会对着空日志打满分——与本仓 `schema:verify` 空转 8 天、`PROFILE-TUNING.md §四` 空表是同一个病：**判据先于数据存在，就是制度在假装运行**。

**落地顺序：档 2 → 档 3 → 档 4，不并行**。档 2 最便宜（半衰期与卷宗都在手上）；档 3 便宜但卡在定义（见 §六 待裁决 D）；档 4 最贵且依赖前两档的数据积累。

**排期见 [`VERSION-PLAN.md`](VERSION-PLAN.md) §4.5.2**（排期是版本面的事，只在这一处记，避免两个真相源）。

## 四、伪 RLHF 联动（具体做什么，不喊口号）

「强有力联动」落成三条可验证的机制，不是加个链接：

1. **记忆操作进审计**：`memory-add` / `memory-tag` / `memory-drop` 三类审计行，带序号与原因。
   判据：`fg case --drop 3` 之后，`AUDIT.log` 里能查到「删了什么、什么时候、删前是什么」。
2. **记忆效果可测**：`[goal]` 条目在后续会话里是否真被引用（`prompt-prefix-shift` 已有观测能力，
   再加一条 `memory-hit` 记录"这条目标出现在第 N 次装配里"）。没有这个，"人格完善"无法证伪。
3. **台账不再空转**：每次 `memory-*` 操作若伴随参数/画像调整，必须在 `PROFILE-TUNING.md §四` 留一行。
   判据：§四 至少一行真实记录——空表就是"制度没在跑"的最硬证据。

**不做**：自动调参、自动淘汰、按遗忘曲线算权重。理由见 `ARCHITECTURE.md`「卷宗条目维护」一节：
时间衰减会先杀掉长期目标，而长期目标恰恰是最该留的那条。

**注入边界（2026-11-02 人类批示，已定）**：不新开 `focus-guard-memory` 段——记忆只并进已有的
`focus-guard-workspace`（同一 owner、同一尾部位置），避免与宿主记忆插件抢段；FG 只注入约束类
内容（决策 / 被否决的命令 / 熔断），用户偏好归 DSH `self-improvement`；静态知识库与人格档不进注入。

### 一、可抄清单（34 条，A/B/C/D 四组；另 1 条已排 3.3.2）

**先纠正我上一版的判断。** 第一版只读了四份 README 级文档，抄出 10 条，大半是参数。
补读全仓 127 个文件（`memory_core/` 25 个模块 + `persistent-self/` 全部 6 个 + 插件与测试）之后，
结论改了三次：

> **第一层：最该抄的不是参数，是它"什么算知道"的判据。**
> **第二层：判据之上还有一块——"开机时怎么重建自己"。**
> **第三层：判据和开机包都要靠注入与产出去落地，那一层它写得更细（见 §五·补 二）。**

合计 **48 条**：A 判据 7 / B 参数 8 / C 工程 9 / D 开机包 10 / E 注入 4 / F 输出 6 / G 幂等 4。

**已在 3.3.2 排期的一条**：注入块带 marker、**重复注入先删旧块**。
对准本仓未修的 DRIFT（2026-10-27 实测 3 会话 **2 DRIFT**，`4cbe896a` 同会话中途 system 两个版本），
也是 `VERSION-PLAN` §1.5① 第三点待定项的**第三选项**：漂移时替换旧块，不只记审计。

#### A 组 · 判据层（7 条）

| # | 它的做法 | 本仓现状 | 抄成什么 | 归属 |
|---|---|---|---|---|
| **A1** | **身份层**（我是什么，不可改，只能追加）与**标准层**（我选什么，可迭代）分开。原文理由：「身份是判断的前提，不是判断的结论」「假记忆第一关撞的该是身份，不是另一条记忆」 | `RULES.md` 只有「已机械化 / 未机械化」，**没有"不可推翻的前提"这一档** | 条款分两类：**前提类**（改了就不是这个系统）/ **选择类**（可迭代）。判据：能不能举出反例 | 4.5 |

| **A5** | 分层按**「多快会变」**排序：身份 → 标准 → 技术 → 事实 → 关系 → 原话 → 想法 → 情绪。「越靠上越稳定，越该每次都给；越靠下越易变，越该少给」。**开机包是索引不是全文**（技术层 1440 字压到 316 token） | 注入块不按变化频率排序；「上次会话：xxx」是**最易变**的一条，却常驻 | 注入按变化频率分层；易变的走 pull。这条同时解释了 DRIFT 为什么发生在那一句上 | 4.5 |

| **A7** | **可推翻性自检**：它把「标准要能被推翻，不然就是循环论证」本身写成一条标准，并给了 `evidence`——「查 `standards` 表里 `superseded_by` 非空的条目，**每条都该有 `superseded_reason`。全是空的说明标准只增不改**」 | 本仓没有"判据系统是否在自欺"的检查。`quality:audit` 查的是"条款有没有交代"，**不查"条款有没有被推翻过"** | 抄这条元判据：**一个只增不改的规则集，等于没有在验证任何东西**。可直接做成 `rules:churn` 报告（近 90 天有无 `superseded_reason` 非空的条款） | 4.5 |

| **F4** | **清空必须兜底**：清洗后为空则随机返回 `嗯？` / `咋了？` / `你说。` / `在。` | 本仓 `noteFail` 已覆盖"写失败"，不覆盖"清洗后为空" | 抄判据：**任何清洗/裁剪都必须定义"剪没了怎么办"**。返回空串是最坏的一种"成功" | 4.5 |
| **F5** | **复读检测**：3 分钟内与上一条 `difflib.SequenceMatcher ratio ≥ 0.85` → 整条收成「嗯」 | 无 | 类比：**同一句话在短窗口内重复出现，是"卡住"的信号**。FG 可映射为"同一 deny 理由连续出现 ≥N 次 → 收成一条并提示换策略" | 4.5 |
| **F6** | **风格化必须自带"不主导"声明**：`hint()` 每条建议末尾固定追加「**情绪只影响语气，不影响判断；对方要你做事就正常做，不要主动提自己的情绪**」 | 本仓无此类声明 | **这条最该抄**。任何"调语气/调措辞/调详细度"的机制，都必须同时声明**它不参与判定**——否则下一任维护者会把它当判据用 | **4.5，优先** |

#### G 组 · 幂等与可解释（4 条）

| # | 它的做法 | 本仓现状 | 抄成什么 | 归属 |
|---|---|---|---|---|
| **G1** | **每个提炼器都测"重复跑返回 0"**：`test_generate_reflection_once_per_day`（同日再跑返回 0）、`test_generate_facts_with_fake_llm`（同日去重返回 0）、`test_learn_skill_with_fake_llm`（相同做法不重复）、`test_import_media_dedupes`（二次导入 0）、`test_generate_lessons_with_fake_llm`（重复跑返回 0） | 本仓的离线工具（`case:audit` / `patterns`）没有幂等断言 | **贯穿全部提炼器的统一判据：幂等**。判据写成"第二次返回 0"，不是"不会重复"——**可断言的形式** | **4.5，优先** |

### 三、不抄（八件，理由不是"不好"）

| 零件 | 为什么不能抄 |
|---|---|
| 五路混合检索的**运行时**（embedding / 向量库） | 本仓记忆的消费者是**闸门**，不是对话模型。`AUDIT.log` 8,540 行是结构化事件（路径=实体、action=类别、时间戳=新鲜度），`JSON.parse` 即可，投影 O(文件数)。它自报检索 p50 **120–140ms**（含 embedding）、纯检索 40ms——拿这个去查一个能直接算的东西，是拿显微镜钉钉子。**抄打分思路，不抄检索器** |
| 生活层（不找你时看书 / 刷视频 / 午睡） | **熔断器不午睡**。FG 没被调用时不应有任何动作 |
| PAD 三维情绪 | 它自己写「有上限、有半衰期、**不主导判断**」。那 FG 拿它做什么？FG 需要的不是情绪，是**偏置**——同一个错误被"第一次犯"无限次重演，缺的是前科，不是心情 |
| HTTP 服务形态（`127.0.0.1:8780` + OpenAI 兼容层 + Bearer token） | FG 是**钩子**，不是服务。多一个常驻进程就多一个存活面、一个端口、一份鉴权 |
| 人格 / 情绪 / 表达层 | 见 §二·补：四档归属已裁决，人格档另立 `src/persona/`，不进 memory |
| `episodes_raw` 保留原始消息 | FG 的原始输入是工具调用，不是聊天。存原文＝把用户的代码与路径再复制一份进卷宗，**扩大泄露面** |
| `intention.py` 提醒解析（「提醒我 / 叫我」+ 中文时间词） | 那是聊天机器人的功能。FG 不在"到点提醒人"这件事上，它只回答"这一步该不该放行"。**抄了也没有消费者** |
| 语音 / 多模态 / 媒体（`voice.py` `media.py` `multimodal.py`） | FG 的输入是 JSON 钩子载荷，没有音频、没有图片。这三块是为聊天消息形态写的 |

**另有两条「不抄，但留档」**——不是不能抄，是抄过来没有对应物，怕后人翻到原表时以为漏了：

| # | 它的数值/做法 | 为什么不进本仓 |
|---|---|---|
| **B8** | 检索新鲜度半衰期 **14 天**；归档删除线 **180 天** | FG 的时间尺度是**会话**，不是"天"。14 天在它那里是"这个事实该不该被检索到"，在本仓没有对应的量——卷宗 TTL 已经用半衰期（`halfLifeOf`）表达同一件事，且单位是小时。换算过来只会得到一串没人能解释的数字 |
| **F3** | 很短的一句日常回复结尾**不挂句号**（`len ≤ 30 and endswith("。")` → 去掉） | FG 的输出去向不是聊天窗口，是**闸门裁决与审计行**。这里去掉句号不是"自然"，是"格式不一致" |

两条都记在 §五·补 一 的 B 组 / 二 的 F 组原表里（归属列标 `—`），此处只做索引。

### 四、UI：3D 脑（`dafeiyu-3d-brain`）——**这个可以抄，而且本仓没有对标物**

**它是什么**：可嵌宿主页面的独立前端。接口是 `window.CortexBrain3D.setData({nodes, edges, memories})`，
three.js + importmap，渲染真实皮层网格（**144,490 + 145,071 顶点**）。首次加载 **15 MB**，
显存约 **200 MB**，桌面 60 fps。`setData` 会先存 `pendingGraph`、等场景就绪再补——挂载前喂数据不会丢。

**本仓现状：没有自己的 UI。** 根目录 `panel-runs.json` 是**采集宿主面板的 token 数据**
（`tools/collect-panel.mjs`），不是 FG 的界面。所以接进来是**新增一个面**，不是替换。

**数据映射几乎是现成的**（`AUDIT.log` → 三个数组）：

| 3D 脑要的 | 本仓对应物 | 映射说明 |
|---|---|---|
| `nodes`（`id`/`name`/`type`/`degree`） | 实体：被读写的文件路径 / 工具名 / 规则条号 | `type` 直接对上：`thing`=文件、`skill`=工具、`topic`=规则条 |
| `edges`（`src`/`dst`/`kind`/`label`/`weight`） | 同会话共现（`cooccur`）+ 同一 `ref` 链（`relation`） | 本仓已有 `seq` / `chain` / `ref`，**边是免费的** |
| `memories`（`id`/`text`/`kind`/`importance`/`created_at`/`entities`） | 审计事件行 | `kind` 映射：`episode`=拦截、`fact`=取证、`review`=收尾结算 |

**核心巧思值得照抄**：位置不是随机撒点，是 `FNV-1a(entities)` 哈希到皮层某个顶点——
**同一条记忆只要 `entities` 不变，位置就不变**。它自己写的理由：「每次刷新位置乱跳，就看不出这块在长东西」。

这句话就是可视化的判据：**图要能回答「哪里在长东西」，否则它只是好看。**

**许可证红线（必须先解决，否则不能碰）**：

| 资产 | 许可 | 能不能进 FG 的包 |
|---|---|---|
| 代码（`brain3d.py` / 前端模块） | 仓库整体 AGPL-3.0-or-later | **能**（与 FG 的 `AGPL-3.0-only` 兼容） |
| three.js | MIT | **能** |
| `cortex/*.bin` 皮层数据（Anderson Winkler） | **CC BY-SA 3.0** | **不能直接打包分发** |

`CC BY-SA 3.0` **不与 GPL / AGPL 兼容**——只有 `CC BY-SA 4.0` 才单向兼容 GPLv3，3.0 不在其列。
FG 是 `AGPL-3.0-only` 且经 npm 分发，把 15 MB 的 CC BY-SA 数据打进包 = 混合许可冲突。三条出路：

1. **运行期由用户自取**（脚本下到 `~/.cache`）→ 属"聚合"而非"结合"，包内不含该数据；
2. 换自有网格（自造低面数皮层，或干脆用球面 / 点云）；
3. 该资产目录独立按 CC BY-SA 分发并保留署名（`LICENSE-ATTRIBUTION.md` 必须留）。

**性能上的现实**：200 MB 显存 + 15 MB 首屏，对一个 hook 插件是**奢侈品**。建议形态：
**独立的 `fg brain` 离线命令 + 本地静态页**，不进 hook 链路、不参与任何判定。
理由同下面那条判据——可视化是给人看的，不该出现在"要不要拦"的路径上。

### 五、不接运行时：两条硬理由

1. **破零依赖**：Python 3.12 + SQLite（`dsh/persistent-self` 还带 numpy，可选 Ollama / whisper）。
2. **它是 push，本仓必须 pull**：`persistent-self` 的用法是 `SelfView(conn).render()` **返回字符串**
   → 必然进 system prompt。这直接撞第一不变量（单一注入层）：两个都往 system 追加，
   谁先谁后、谁删谁的 marker、漂移算谁的。
   真要接，唯一安全形态：**FG 主动去问一句，结果进 deny 理由（尾部），不进 system**。

### 六、判据（写死，避免反复讨论）

> **记忆的消费者是闸门，不是模型。前科不需要被回忆，只需要在越线那一刻被想起来。**

推论两条，一并写死：

1. **凡"给模型看"的，一律 pull，不进 system**（否则抖前缀）；凡"给人看"的，一律离线，不进判定链路。
2. **抄的是判据与参数形态，不是实现**。它的 SQLite + embedding + HTTP 是它宿主的形状，不是问题本身的形状。

本参照使 §六 待裁决 C（`memory-hit` 是否进注入）明显倾向 **① 只写审计不进注入**，
但裁决权仍在人类，不代拍。

## 七、边界（写死，避免误读）

- 本计划**不改** `workspace.json` 的 schema——标签仍用文本前缀，零迁移。
- 本计划**不做**自动淘汰、不做遗忘曲线、不做无人批准的参数回写。
- 本计划**不引入**任何外部记忆服务的运行时（§五·补）：零依赖是硬约束，抄设计不抄依赖。
- 本计划**不做**常驻进程、不监听端口、不加鉴权层——FG 是钩子，不是服务。
- 任何**可视化**都不进判定链路：它是给人看的，不参与"要不要拦"（§五·补 三）。
- 4.5 之前若 M1/M2 未完成，**不允许**为赶版本跳过验收——宁可延后 4.5。
