# 记忆检索离线评测（结构化 / 向量 / 混合）

> **状态**：参考 · 适用版本 3.5.3 · 最后核对 2026-11-26

> 工具：`npm run memory:recall`（`packages/core/tools/memory-recall-eval.mjs`）。
> 本文件只放**结果、限制与接线建议**；脚本改口径时同步重跑并改这里。

> **口径变了（2026-11-26）**：`decisions` 里只收**带标签的条目**（`[goal]`/`[done]`/`[note]`），
> 无标签的一律排除并只计数——它们是下架前自动落账的「人类指令原文」，不是结论。
> 语料或标注为空时脚本**不打印召回率**，直接报「结论无效」并 `exit 2`。
> 因此 §二 的表是**历史读数**，用旧口径测的，不能当「检索已验证」。

## 一、测什么

同一查询集下比较三种"把记忆给模型"的方式：

- **S 结构化全量**：`.focus-guard/workspace.json` + `.ai/CASE_FILE.md` 的条目全部注入；
- **V 纯向量**：对同一批条目做 TF-IDF 余弦检索，取 top-k；
- **H 混合**：钉住「约束/下一步/最近 3 条决策」，其余走向量 top-k。

另加**会话语料**模式：历史会话按回合切块（≈800 字/块）当语料，测大语料下的召回上限。
查询 = 历史会话用户消息（≥12 字、去重；本轮 1,070 条）；相关性 = 词项 Jaccard ≥ 0.05（启发式 qrels）。

## 二、结果（2026-11-24，离线；**旧口径**，见上）

### T1 记忆库（15 个 unit / 24 条可标注查询）

| 方法 | Recall@1 | Recall@3 | tokens/查询 | 延迟 |
|---|---|---|---|---|
| S 结构化全量 | 100% | 100% | **704** | 0ms |
| V 向量 | 100% | 100% | **208 / 265** | 0.05ms |
| H 混合（钉 3 条） | 100% | 100% | **240 / 297** | 0.03ms |

> **这张表不能用来选方案**：15 个 unit 里 10 条是下架前的指令原文、5 条是 CASE 段；24 条"可标注查询"
> 是靠词项 Jaccard 自动配上的。三个 100% 里，S 的 100% 是「全量注入必然包含全量」的同义反复，
> V/H 的 100% 只说明这 24 条查询与那 15 条里某条词面重叠。按新口径重跑，语料只剩 5 条 CASE 段、
> 标注 0 条，脚本直接报「结论无效」。**T1 目前没有可用数据。**

**token 比**：S/V = **3.4×**（@1）、**2.7×**（@3）；S/H = 2.9×（@1）、**2.4×**（@3）；
H 比 V 多付 12%（钉选开销），换来"这些条目一定在"。

### T2 会话语料（2,155 块 / 608 条可标注查询）

| 方法 | Recall@1 | Recall@3 | Recall@5 | tokens/查询 | 延迟 |
|---|---|---|---|---|---|
| V 向量 | 7.1% | **69.6%** | 77.3% | 183 / 563 / 962 | 38–40ms |
| H 混合 | 7.1% | **69.6%** | 77.3% | 215 / 595 / 994 | 38–40ms |
| S 结构化（覆盖代理） | — | — | — | 704 | 0ms |

- top-1 只有 7%：词袋向量在原始会话文本上几乎没有区分度；**k=3 才可用**。
- 混合在大语料上**没有提升召回**（钉选条目与原始块词面不重叠），只多付 12% token——
  它的价值是"保证"，不是"更准"。
- S 的「覆盖代理 0%」是摘要 vs 原文的词面重叠，**不代表结构化记忆没记住**。

## 三、定量结论

| 维度 | 纯结构化 | 纯向量 | 混合 |
|---|---|---|---|
| 召回（记忆库） | 100%（保证） | 100%（本语料无区分度） | 100%（钉选保证 + 检索） |
| 召回（大会话语料 @3） | 不可用（不是原文检索） | 69.6% | 69.6% |
| tokens/查询 | 704（全量） | 208–962（随 k） | 240–994（钉选 + k） |
| 延迟 | 0ms | 0.05ms（小库）/ 38–40ms（大会话） | 同向量 |
| 失效风险 | 无遗漏，但占固定预算 | 漏召回；嵌入/索引换代失效 | 漏召回；钉选保证安全条目 |

**推荐**：三层接线，而不是三选一。安全/执法事实绝不交给向量。

## 四、推荐接线

- **Tier 0 必须保证**（约束、红线、最近 3 条决策）：`fg_workspace` 结构化返回，钉选在前，
  ≈240 tokens；不经过检索、不设 top-k。
- **Tier 1 主记忆**（全部决策 / CASE 摘要）：`fg_workspace` 按需拉取全量，≈704 tokens；
  模型需要交接信息时调。
- **Tier 2 历史原文**：新增 `fg_memory_search`，对"会话块 + 文档"做向量 top-3（≈563 tokens，
  38–40ms），只在翻旧账/查原话时调；结果必须带 `file:line` 或 session id 可核。
- **预算**：单次检索 ≤600 tokens、K 默认 3；`k=1` 只有 7% 召回，不使用。
- **禁止**：用向量结果替代 Tier 0 条目；用向量做"该不该拦"的判定依据。

## 五、迁移步骤

1. **索引器**（待建）：在 `packages/core/tools/` 下新增 `memory-index.mjs`，离线构建 `.focus-guard/vector-index.json`
   （TF-IDF 起步；`--embedder neural` 留接口，等本地模型/API 再接）。
2. **检索工具**：注册 `fg_memory_search(query, k=3)`，返回条目文本 + `file:line`/session id + 命中分；
   工具描述写明「历史原文检索，不用于约束判定」。
3. **钉选进结构化**：`renderWorkspaceSection` 保证 constraints / 最近 3 条决策排在最前且不被截断。
4. **路由不加常驻段**：两个工具靠描述区分用途，不往 system prompt 加路由文本（避免每步付费）。
5. **验收门槛**：`npm run memory:recall` 跑 k=1/3/5；向量 k3 ≥65% 召回、≤600 tokens、≤60ms 才算达标；
   不达标不默认开，检索工具保持"按需"。**前提是 `labelled > 0`**——脚本 `exit 2` 时先去补语料，
   不许拿本文件 §二 的历史数字顶替（那是旧口径）。
6. **神经嵌入替换**：先离线对比（同一 qrels），确认相对词袋有提升再切换，保留回退开关。

## 六、限制（必须一起读）

- 向量 = **TF-IDF 稀疏向量**，不是神经语义向量；本机无本地模型/API key，语义召回未测。
- qrels 是词项启发式，不是人工标注；**只看相对差，不看绝对值**。
- 会话语料按回合切块，切法会改变数字；T1 语料仅 15 unit，无区分度。
- **语料只收带标签结论**（2026-11-26 起）：无标签 `decisions` 是指令原文，排除后 T1 语料为 0 条结论，
  `labelled=0` 时脚本报「结论无效」并 `exit 2`——**没有数据时它拒绝出数字**，这不是故障。
- S 的覆盖代理与 V 的 Recall 口径不同，不能直接相减。
