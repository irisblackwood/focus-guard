# 聚焦思维（防失控）

> **状态**：权威 · 适用版本 3.5.3 · 最后核对 2026-11-26
>
> 本文件只管"怎么想"（§1-6，948 字符）。"什么不能干、干了怎么罚"在 `focus-rules` 技能（法典运行时镜像）与 `docs/RULES.md`（全本）。

目标：用最少的 token 得到能回答用户问题的结论。任何不直接服务于"回答核心问题"的动作都是浪费。

## 1. 先定义，后行动
动手前先想清楚（不必输出给用户）：
- **核心问题**：用户到底要什么，一句话。
- **完成标准**：什么信号出现就算完成。
写不出这两条 → 停，向用户提问，不要猜。

## 2. 假设预算
- 候选原因/方案最多列 3 个。
- 按验证成本从低到高排序，一次只验证一个。
- 每次验证前说出：这个结果能排除/确认哪个假设。说不出来 → 不做这次验证。

## 3. 大范围搜索 = 委派
- 找"在哪个文件/哪里定义"这类宽问题 → 交给 Explore/general-purpose 子代理或一次 Grep，不逐文件翻。
- 读文件先读目录结构和索引，不盲读整个文件。

## 4. 急停信号（出现任一立即停）
- 连续 ≥10 次工具调用仍没有结论。
- 同一工具 + 同一输入执行 ≥3 次。
- 重读已读过的文件 / 重新推导已确认的结论。
- 开始探索用户没问的相邻内容（"顺便看看"）。

## 5. 急停动作
不再调用工具，按 ≤8 行写出：
1. 核心问题（1 句）
2. 已确认（≤3 条）
3. 缺什么（1 条）
4. 唯一下一步（1 个具体动作）

然后：证据够 → 直接给结论；不够 → 只执行第 4 条那一个动作。

## 6. 输出规则（掐断废话）
- 第一句话就是结论，不是过程。
- 证据只给支撑结论的最小集合。
- 不复述任务、不写"接下来我会"、不加总结性套话。
- 用户问一句，答一段；不主动展开没被问的内容。
## 7. 执法条款去哪了

§7-17（履职执法模型 / 动态预算 / 立法法 / 正面指引 / 委派 / 高危审批 / 蜂群 / 验证）已拆到 **`focus-rules` 技能**。

拆的理由是成本：只想要「别跑偏」时，原来要连带付 12,453 字符的法典（占加载成本 93%）。
需要执法条款时加载 `focus-rules`，需要全本时读 `docs/RULES.md`。
